# 이미 받은 수납·이미 지급한 할인 기록

직원 정정 기능의 별도 후속 변경이다. 실제 결제·환급·송금을 실행하지 않는다.

- 기존 직원 신원과 정정 권한을 유지한다. 통합어드민의 누락 수납 기록은 기존 수납 권한도 확인한다. 수령완료 주문도 수령상태·시각·태그를 그대로 보존한다.
- `historicalReceipts`는 이미 받은 누락분만 보충 영수증으로 추가한다. 원영수증 금액·수단·시각은 덮지 않는다. 실제 업무일과 수단, 이미 받은 사실이 필요하며 정확한 시각은 null, 대략적 시각은 메모로 분리한다. 기록시각은 실제 저장시각이다.
- 최종 청구액, 수량, 보충 영수증, 이미 반환한 금액, 개인 작업자·사유·전후 snapshot을 하나의 D1 batch에 연결한다. 미수납·반환 초과 및 수령완료 미수납 방지 규칙은 유지한다. 보충 수납은 최종 청구와 이미 반환한 금액으로 확인되는 부족액을 넘을 수 없다.
- `DISCOUNT_ALREADY_PAID`는 직원이 확인한 기지급 할인 사실이다. 최종 청구액에는 그 할인을 이미 반영해서 입력한다. 이 기록은 기존 Flying Pass 환급표에 중복 삽입하지 않으며, 회원 마스터나 검증된 회원 등급으로 자동 변경하지 않는다. 기존 환급이 있거나 같은 기지급 할인이 이미 있으면 중복 기록을 거부한다. 이 내역이 있으면 기존 환급으로 다시 지급을 시작할 수 없다. 새로운 등급으로 추가 할인 여부를 검토할 때는 이 기지급 기록부터 대조한다.
- 반환수단 UNKNOWN과 시각 null을 지원한다. 원수납 총액 − 기록된 반환·기존 환급 = 순수납이다. 내부 `general_returned_amount`는 기존 호환 합계 필드로 모든 직원 정정 반환을 한 번 합산하며 화면·이력은 반환 구분을 별도로 표시한다. 기지급 할인은 청구에서 다시 빼지 않는다. 미상 수단은 현금/QR로 임의 배분하지 않고 마감 차액을 불확정으로 표시한다.
- 추가짐 이력의 수납일이 이미 최종 마감됐거나 기존 Flying Pass 환급이 확정된 주문도 일반 보충 수납을 기록할 수 있다. 일반 추가수납의 open-day 보호와 원영수증 보존은 유지한다. 세 수납 보호 트리거는 미봉인 정정과 감사, 주문·직원·기록시각·receiptId·금액·수단·실제 업무일이 모두 일치하는 새 보충행만 허용한다. 기존 payment_id 또는 수납 키 충돌과 진행 중 환급은 계속 차단한다.
- 원래 마감 계수와 스냅샷은 보존한다. 현재 재집계에 실제 업무일의 보충 수납과 반환이 반영된다. 반환수단을 나중에 확인하면 기존 미상 반환을 배분하며 새 반환을 만들지 않는다.
- 원본·보충 영수증, 감사, 정정 metadata는 불변이다. 영수증 별 UUID, 전후 revision/family scope CAS, 같은 요청 재조회, unique 역사 영수증 키와 REPLACE 충돌 방어를 사용한다.

적용은 기존 직원 정정 migration 다음 `20261101_staff_historical_receipts.sql` 순서다. 기존 후보 migration을 수정하지 않았다. 현재 운영 미적용. 기존 직원 정정 기능이 먼저 개방된 경우 업그레이드 동안 새 정정 쓰기만 잠시 OFF로 두고 두 migration/소스 버전이 맞는지 확인한 후 다시 개방한다. 기존 고객 접수·환급·추가짐은 독립적으로 유지한다. 새 metadata/영수증이 생긴 뒤 구 schema/view로 역 migration하지 않는다. 중단은 정정 기능 flag를 OFF로 두고 신형 조회·원장 코드를 보존하는 방식이다.
